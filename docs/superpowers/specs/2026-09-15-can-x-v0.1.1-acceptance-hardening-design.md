# CAN-X V0.1.1 Acceptance Hardening Design

## Scope

V0.1.1 closes V0.1 architecture proof gaps without adding CAN protocol or
hardware features. Work is divided into four independently verifiable stages:

1. documentation naming consistency and Recorder pressure hardening;
2. one shared frontend realtime stream and latency instrumentation;
3. packaged Windows Python Runtime and Tauri distribution proof;
4. complete regression matrix, independent review, and acceptance report.

This document records the approved system design. Each stage receives a focused
implementation plan before code changes begin.

## Recorder pressure

The normative decision is ADR 0001. Capture and UI streaming continue after a
Recorder pressure/write failure, while the session becomes `degraded`. Archive
enqueue has a finite deadline, failure is structured and observable, and stop
remains bounded.

Runtime state is separated into:

- process state: ready or failed;
- capture session state: idle, running, degraded, failed;
- Recorder state: idle, recording, stopped, failed.

These states prevent a healthy process with an incomplete recording from being
misreported as either fully healthy or completely unavailable.

## Shared frontend realtime stream

One workspace-owned provider creates one WebSocket and one frame Worker. The
Worker owns a bounded frame ring and publishes governed snapshots to a small
external store. Trace and Plot subscribe to projections from that store. React
does not receive per-frame updates or own unbounded history.

Capture-session identity is carried with each batch. A stream ID change clears
the Worker ring, sequence baseline, and all view snapshots before the new batch
is published. Trace freeze records a Trace-only snapshot cursor; it never pauses
the shared socket, Worker, store, or Plot subscription.

The shared store exposes connection state, current stream ID, bounded snapshot,
sequence gaps, UI drops, and timestamp measurements. It reference-counts mounted
consumers and closes its Worker and WebSocket exactly once when the workspace
provider unmounts.

## Packaged Runtime and desktop lifecycle

PyInstaller is the initial Windows packaging proof because it preserves Python
Runtime ownership and produces a repeatable executable without requiring a user
Python installation. Dependency license and maintenance notes will be recorded
before adoption.

Development mode may use `CANX_RUNTIME_PYTHON` or the repository `.venv`.
Production mode resolves only the bundled `canx-runtime.exe`; it must return a
structured startup error when absent and must never fall back to system Python.
Tauri bundle resources include that executable and enable a minimal Windows
artifact. Signing, updates, and installer polish remain outside V0.1.1.

The smoke path launches the distribution-owned Runtime, validates `/health`,
starts Virtual Capture, observes one shared stream in Trace and Plot, stops and
flushes capture, exits the desktop, and proves the child process exits. GUI
execution blocked by host policy is reported as `NOT VERIFIED` with evidence.

## Performance instrumentation

Measurements use monotonic timestamps and nullable availability. Missing
measurements are `null`/`NOT VERIFIED`, never zero. Runtime batch publication
records Runtime-to-WebSocket timing metadata. The Worker measures decode and
snapshot publication. Trace and Plot measure governed React update work. The
acceptance report records environment, dataset, duration, and observed values;
it does not declare a production SLA.

## Error and cleanup contract

Every new boundary failure has a stable code, human message, recoverability, and
context. Background task exceptions are consumed and surfaced. Queue, Worker,
WebSocket, Runtime child, and file handles have bounded cleanup paths. Tests use
hard timeouts for pressure and shutdown behavior.

## Verification

Each stage follows red-green-refactor testing. Final verification includes the
complete Python, frontend, and Rust matrices; focused saturation, soak, shared
stream, packaged Runtime, and smoke tests; a source scan for `AGENTS.md`; and an
independent review for silent loss, deadlocks, leaks, counter ambiguity, fake
metrics, hidden exceptions, and unsafe fallback.
