# CAN-X V0.1.1 Recorder Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Recorder saturation and write failures finite, explicit, observable, and safe while capture and the UI stream continue in a degraded session.

**Architecture:** Active subscribers receive each normalized frame concurrently. The lossless archive subscriber uses a bounded enqueue deadline; timeout or Recorder write failure disables only archive delivery, marks Recorder failed and the session degraded, while the lossy stream stays active. Runtime status and metrics expose stable failure diagnostics and stop cancels failed work with bounded cleanup.

**Tech Stack:** Python 3.13, asyncio, Pydantic, FastAPI, pytest, Ruff, mypy

## Global Constraints

- Preserve Tauri 2, React 19, TypeScript, Python 3.13, FastAPI, WebSocket, MessagePack, and python-can.
- Do not add CAN protocol, hardware adapter, Agent planner, cloud, account, or licensing functionality.
- Recorder remains lossless while healthy; no frame may be silently dropped.
- Queue capacity and pressure deadline are finite and observable.
- Every failure must expose code, message, recoverability, and context.
- All pressure and shutdown tests use hard timeouts.
