# CAN-X V0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and measure the smallest end-to-end CAN-X architecture proof from deterministic Virtual CAN through a headless runtime, recorder, binary stream, bounded desktop Trace/Plot, and read-only `trace.summary` tool.

**Architecture:** Tauri owns only desktop and Python sidecar lifecycle. The headless Python runtime owns domain data, capture, recorder, metrics, and Agent tools; binary batches cross into a Web Worker and only bounded snapshots reach React.

**Tech Stack:** Tauri 2, Rust, React 19, TypeScript, Vite, Dockview, Zustand, TanStack Query, TanStack Virtual, i18next, ECharts, Python 3.13 target, FastAPI, WebSocket, MessagePack, pytest, Vitest.

## Global Constraints

- Preserve `UI != CAN Runtime != Agent Runtime != Storage`.
- Use Python 3.13 as the target; record Python 3.12-only local execution separately.
- Use HTTP/JSON for control and binary MessagePack WebSocket batches for frames.
- Keep capture/recorder integrity ahead of UI refresh and animation.
- Do not create a direct UI/Agent-to-`adapter.send()` path.
- Do not reuse CAN-Space/CanLab code or introduce PyQt/Qt state patterns.
- Use translation keys for production UI text and strict TypeScript without `any`.
- Do not claim physical hardware or macOS verification.

## Plan self-review

- Every PRD/SPEC V0.1 deliverable maps to Tasks 1–16 and the factual review in Task 17.
- Public interfaces use the same field names as `docs/V0.1_TECH_VALIDATION.md`.
- Recorder and stream remain sibling consumers; no UI-owned capture/storage path exists.
- Physical hardware, macOS, full protocols, arbitrary code, cloud, and production storage remain outside the plan.
- Each behavior task begins with a test that must fail for the missing feature before implementation.
