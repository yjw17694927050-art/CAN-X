## 1. Phase objective

Give the Runtime a formal, typed, **read-only** Project inspection / read-model API, so no
future Desktop has to ask a DBC endpoint whether a directory is a valid CAN-X project.

```text
caller supplies explicit project_path
        ↓
GET /project/inspect
        ↓
FastAPI adapter (canx/api/project.py)
        ↓
ProjectService.open          ← the project domain stays the authority
        ↓
validated CAN-X project (project.json + project.db + schema + agreement)
        ↓
ProjectHandle / ProjectMetadata
        ↓
temporary handle closed
        ↓
typed, immutable read model
```

Not in scope, and not built: a current project, a project picker, project create / delete /
rename / repair / upgrade, recent-project history, any Desktop work, any DBC change.

## 2. Scope implemented

- **One new Runtime endpoint**: `GET /project/inspect?project_path=<path>`.
- **One new response model**: `ProjectInspectResponse` — `project_id`, `display_name`,
  `schema_version`, `created_at`, `updated_at`, and nothing else.
- **A new router module** `runtime/canx/api/project.py` (188 lines, of which most is the
  reasoning for the four load-bearing properties), mounted from the application factory
  alongside the Trace and DBC routers.
- **Request-scoped handle lifecycle**: the project is opened, read and closed *inside one
  request*; the handle is taken as a context manager, so "opened" and "closed" cannot be
  separated by an early return.
- **Blocking work off the event loop**: the whole open → read → close sequence runs under
  `asyncio.to_thread`.

### 2.1 The exact contract

```text
GET /project/inspect
Query:    project_path: string            (required; passed through unmodified)
200:
{
  "project_id":     "2f1c3d4e-5a6b-4c7d-8e9f-0a1b2c3d4e5f",
  "display_name":   "Powertrain Rig",
  "schema_version": 1,
  "created_at":     "2026-09-17T16:40:12.345678+00:00",
  "updated_at":     "2026-09-17T16:40:12.345678+00:00"
}
400:  any typed `project.*` domain failure, in the shared five-field envelope
422:  api.request_validation_failed  (missing `project_path`)
```

`project_id` comes from the validated project identity (manifest and database agreement);
`display_name` / `created_at` / `updated_at` come from the canonical metadata row;
`schema_version` comes from the canonical manifest. None of them is derived from a file name
or a directory name.

## 4. Architecture / boundary statement

```text
UI  ≠  CAN Runtime  ≠  Agent Runtime  ≠  Storage
```

- **The project domain remains the authority.** The adapter never reads `project.json`,
  never opens `project.db`, never runs a SQL query of its own and never decides for itself
  what a valid project is. `ProjectService.open` performs path → manifest → database →
  schema → identity-agreement validation, and this module only projects its result.
  There is no second project parser to drift from the first.
- **No global current project.** The endpoint is stateless: every request supplies its own
  `project_path`, opens its own handle and closes it before answering. No
  `current_project`, no `active_project`, no module-level `ProjectHandle`, no cached handle,
  no session state.
- **The response is not a filesystem authority.** The caller's path, the manifest path, the
  database path and every internal directory (`dbc/`, `data/`, `cache/`, `logs/`, …) are
  absent from the projection.
- **`project_path` is not normalized.** It reaches `Path(...)` exactly as the caller wrote
  it: no `resolve()`, no `expanduser()`, no `lower()`, no separator rewriting, and no
  hand-written cross-platform path parser. The project domain decides what the string means;
  rewriting it would silently inspect a different directory than the one requested.
- **No DBC coupling in either direction.** The project surface does not import the DBC
  surface, and no DBC endpoint was changed. `DBC` is not a project validator and the project
  endpoint is not a DBC validator.

### 4.1 Error semantics

The domain errors are the existing ones; **no new taxonomy and no second mapping table was
created**. `ProjectError` already had an application-level handler
(`runtime/canx/api/app.py`) and a status rule (`status_for` in `runtime/canx/api/errors.py`
→ 400 for every project failure), so `runtime/canx/api/errors.py` needed **no change at
all** — the file was deliberately left untouched.

The codes this endpoint can therefore return, as produced by the domain:

```text
project.not_found                    project.manifest_missing
project.not_a_directory              project.manifest_malformed
project.manifest_unreadable          project.unsupported_format
project.unsupported_schema_version   project.database_missing
project.database_schema_invalid      project.database_unreadable
project.metadata_missing             project.metadata_invalid
project.identity_mismatch            project.close_failed
```

Every one is reported as the shared five-field envelope (`code` / `message` / `details` /
`recoverable` / `source = "project"`) with a **400**, never downgraded into a 500. Framework
request-shape validation keeps its own **422** (`api.request_validation_failed`,
`source = "api"`), and the two layers are never merged.

### 7.1 Event-loop boundary — how it is asserted

Being an `async` route says nothing about where the work happened, so the assertion is about
the *work*: `canx.api.project._open_project` is wrapped to record `threading.get_ident()`
**before** it runs, and every recorded thread must differ from the loop's thread. The record
happens before the call because a refused target never returns a handle — and validating a
refused target is exactly the expensive part that must not run on the loop.

This is a real bound, not a formality: `ProjectService.open` walks the filesystem, reads and
parses `project.json`, opens SQLite, reads metadata and verifies every table of the schema.

### 7.2 Handle ownership — how it is asserted

"Closed" is observed, not asserted from reading code: the spy keeps every
`ProjectHandle` the request opened and the tests assert `handle.closed is True` for each, and
that no handle survives its request. Three paths are covered separately:

```text
success                       → handle closed, exactly one open per request
failure after open            → read_metadata raises  → handle still closed (400 project.metadata_unreadable)
response construction failure → _inspect_payload raises → handle still closed, nothing left to leak
25 sequential requests        → 25 opens, 25 closes, 0 leaked
```

The response-construction case is the ordering proof: the projection is built *after* the
owned scope has exited, so cleaning up cannot depend on the response succeeding.

## 18. V0.3-11-FINAL — Empty Project Path Contract Hardening

> **Trigger**: independent acceptance of the initial submission —
> `Final Acceptance: NOT PASS · Status: OPEN · P0: 0, P1: 1, P2: 0`.
> The P1 was: *empty `project_path` was interpreted by `Path("")` as Runtime CWD.*

### 18.1 Root cause

```python
async def inspect_project(project_path: str)          # no contract on the value
...
ProjectService().open(Path(project_path))             # Path("") is Path(".")
```

`Path("")` is not "no path" — it is `Path(".")`, resolved against the process working
directory at `exists()` time. So `GET /project/inspect?project_path=` did not fail to name a
project; it named *whatever directory the Runtime was running in*, and answered `200` with that
project's identity whenever that directory happened to be a valid CAN-X project.

The initial submission's test for this case asserted exactly the wrong contract:

```python
# tests/unit/api/test_project_api.py — REMOVED; it asserted 400 project.* as correct
async def test_the_runtime_normalizes_nothing_about_the_supplied_path(...)
```

It passed only because the pytest working directory is not a CAN-X project. That is luck, not
evidence — and it is why the defect survived the initial self-verification.

### 18.2 Fix

```python
from typing import Annotated
from fastapi import APIRouter, Query

@router.get("/inspect", response_model=ProjectInspectResponse)
async def inspect_project(
    project_path: Annotated[str, Query(min_length=1)],
) -> ProjectInspectResponse:
```

`min_length=1` is deployed as a *contract* rule, not a path policy. It is the same declaration
style already used in this codebase (`runtime/canx/api/dbc.py:526` —
`stream_id: str = Field(min_length=1)`). Nothing else changed: no `resolve()`, no
`expanduser()`, no `lower()`, no separator rewriting, no canonicalization. A non-empty value
still reaches `Path(project_path)` verbatim, and whitespace-only values are still the project
domain's to judge.
