### 2.2 Round 2 — the last open P1

Round 1 of the remediation left one P1 open: live DBC decode **request fragmentation**.
The bounded decoder cache had removed the repeated *parse/compile* work but not the
*request count*, so a viewport alternating two channels was submitted one frame per
request; 400 alternating frames over two different DBCs cost 400 HTTP requests at
316 frames/s against a virtual capture producing 1000 frames/s.

Round 2 closed it by separating the two containers that had been conflated:

```text
capture    FrameBatch      a contiguous slice of ONE stream's numbering — unchanged
decode     DecodeFrameSet  ordered, non-repeating, bounded, gaps allowed
```

with `POST /dbc/assets/{asset_id}/decode-frames` as the decode-specific surface.
`POST /dbc/assets/{asset_id}/decode-batch` keeps its contract and still refuses a
non-contiguous batch; one test asserts both surfaces against the same payload. The
full root cause, design rationale and measurements are in
`docs/acceptance/v0.3-code-audit-remediation.md` §9.

No second truth surface was created: the acceptance and current-state documents carry
the same statement, and no product code was touched to make the description true.
