# V0.4-08-FIX-1 — Replay Project Authority Closure

> **Task**: V0.4-08-FIX-1 · **Owner**: Sub-Agent C (Replay Track)
> **Worktree**: shared staging `fix/v0.4-wave1-fix1-staging` (HEAD `481be34c`)
> **Status**: HANDOFF_READY — implementation complete, all four gates re-run green

## The finding (verified)

`ReplaySession.open(project_root, ...)` never opened the root through the project
domain. It went straight from `_resolve_data_session(root, session_id)` to
`DataSessionService(root).get_session(session_id)`, which reads `project.db`
directly. The CAN-X project authority — `ProjectService().open()`
(`runtime/canx/project/service.py:237`), which validates the path, `project.json`,
the manifest, `project.db`, the database schema, manifest/database identity
agreement and the supported version — was never consulted. Replay therefore
trusted a directory that could be anything at all, as long as a database with the
right table shape happened to sit in it.

## The fix

`ReplaySession.open()` now calls `ProjectService().open(Path(project_root))`
**first**, and only after full validation succeeds does it build
`DataSessionService(handle.root)` / `QueryService(handle.root)` /
`SessionReplaySource` from the validated root. The `ProjectHandle` is closed
immediately after validation (`_close_project`), before the session is resolved,
so the replay reads through the query domain's own short-lived connections rather
than through the authority's handle.

No project validation was copied into the replay package: replay does not read
`project.json`, does not compare `project_id`, and does not inspect the SQLite
schema by hand.

Project-domain failures are translated into the existing typed
`ReplayProjectError` (`runtime/canx/replay/errors.py`). Only the project's stable
cause code crosses the boundary, in `details["cause"]`:

| Project cause | Replay outer code |
| --- | --- |
| `project.not_found`, `project.not_a_directory` | `replay.invalid_project` |
| `project.manifest_missing` | `replay.project_unavailable` |
| `project.manifest_malformed` | `replay.project_unavailable` |
| `project.database_missing` | `replay.project_unavailable` |
| `project.identity_mismatch` | `replay.project_unavailable` |
| `project.unsupported_schema_version` | `replay.project_unavailable` |
| any other `ProjectError` | `replay.project_unavailable` |

The project error's own `details` are deliberately **not** copied: they carry
absolute host paths, which must not leave the project layer through a replay
error. No raw SQLite exception, traceback or secret crosses the boundary either.
